# Neiry Music Emotion Tracker

Десктопное приложение для Windows, которое в реальном времени измеряет эмоциональный и психофизиологический отклик на музыку с помощью нейрогарнитуры **Neiry Headband** (Capsule API), автоматически синхронизирует биосигналы с текущим треком из **Spotify** (или любого системного плеера) и накапливает адаптивный эмоциональный профиль каждого трека между сессиями.

## О проекте

Обычные музыкальные сервисы ориентируются на жанры, темп и лайки, но не знают, как конкретный трек реально влияет на состояние слушателя. **Neiry Music Emotion Tracker** решает эту задачу через связку реальных биосигналов (ЭЭГ + ФПГ + MEMS) и событийного трекинга воспроизведения:

- фиксирует, в какой момент начался и закончился каждый трек;
- оценивает эмоциональный фон относительно персонального бейслайна и фильтрует шум;
- сохраняет сырые данные сессии в **HDF5** для офлайн-разбора;
- накапливает историю прослушиваний в **SQLite** и перебалансирует веса трека по мере новых сессий, чтобы выдавать рекомендацию — какую реакцию трек вероятнее всего триггерит именно у вас.

## Ключевые возможности

- **Живой мониторинг биосигналов (Capsule API):** работа с 4-канальным ЭЭГ (O1, O2, T3, T4 + Fpz, биполярный и монополярный режимы), ФПГ (ЧСС, индекс напряжения, индекс Каплана), MEMS (акселерометр, гироскоп), импедансом электродов и всеми классификаторами (`Emotions`, `Cardio`, `Productivity`, `PhysiologicalStates`).
- **Умный BLE-сканер:** автоматический поиск устройств по `DeviceType.Any` (поддержка Neiry Headband и BrainBit) с повторными попытками, диагностикой статуса Bluetooth и переключением на виртуальные устройства (`SinWave`, `Noise`) или встроенный `Demo`-режим без повязки.
- **Автоматическое отслеживание Spotify без OAuth-токенов:** интеграция с системным медиа-контроллером Windows (**Windows SMTC**), который перехватывает название трека, исполнителя, паузы и переключения из Spotify Desktop и других плееров.
- **Полная калибровка с сохранением профиля:** пошаговое прохождение всех 3 этапов (`Calibrator.calibrate_quick()` → `Productivity.calibrate_baselines()` → `PhysiologicalStates.calibrate_baselines()`) с сохранением параметров в SQLite и возможностью быстрого импорта в следующих сессиях.
- **Гибридное хранилище (HDF5 + SQLite):** поточная запись сырых сигналов, таймлайна эмоций и маркеров треков в `.h5` (совместимо со структурой Neiry 3.0) + реляционная база истории треков в SQLite.
- **Низкая нагрузка на CPU:** пакетная буферизация сырых сигналов (250 Гц ЭЭГ/MEMS, 100 Гц ФПГ), развязанная перерисовка графиков на 3 Гц без программного сглаживания, кэширование WinRT-менеджера и опция отключения записи сырых потоков.

## Аналитическая модель и ребалансировка весов

Для каждого прослушивания длительностью от 20 секунд (`MIN_TRACK_LISTEN_SEC`) строится итоговый вектор из 5 состояний: **Расслабление**, **Фокус и концентрация**, **Вовлечённость / драйв**, **Стресс / напряжение** и **Усталость / спад**.

1. **Оценка качества среза (`q ∈ [0.1, 1.0]`):** учитывает максимальное сопротивление электродов (порог хорошего контакта — 1000 кОм), долю артефактов ЭЭГ, флаги артефактов ФПГ и резкие движения головы по акселерометру MEMS.
2. **Нормализация относительно бейслайна:** метрики `Productivity` и `Cardio` (индекс напряжения) нормализуются через сигмоиду относительно базового уровня текущей сессии, объединяясь с быстрыми оценками `Emotions` и вероятностями `PhysiologicalStates`.
3. **Адаптивная ребалансировка между сессиями:** при расчёте итогового профиля трека свежие прослушивания весят больше старых за счёт экспоненциального затухания (`RECENCY_DECAY_LAMBDA = 0.78`) с учётом качества сигнала и длительности прослушивания:
   `weight_i = (lambda ** age_rank) * quality_i * duration_factor_i`
   Если первая сессия по треку показала расслабление, а следующие три — стресс, система автоматически сместит итоговую рекомендацию к стрессу и зафиксирует смену тренда в колонке **«Тренд между сессиями»**.
4. **Оценка уверенности (Confidence):** рассчитывается по числу прослушиваний, отрыву лидирующей эмоции от второй и согласованности последних сессий.

## Интерфейс (3 вкладки)

- **Сессия (Live):** панель BLE-сканирования, статус батареи и контакта электродов, мастер калибровки/импорта, карточка текущего трека из Spotify, живые графики эмоций и ЧСС (`pyqtgraph`), лог событий.
- **Отчёт / HDF5:** просмотр текущей или любой ранее сохранённой `.h5`-сессии — таймлайн эмоций с цветными сегментами треков, пиками внутри каждого трека и сводной таблицей.
- **Библиотека треков:** накопленная база всех прослушанных треков с фильтром по эмоциональному триггеру, итоговой рекомендацией, уверенностью, трендом и детализацией всех прошлых прослушиваний по клику.

## Архитектура и структура проекта

| Путь | Назначение |
| :--- | :--- |
| `app.py` | Точка входа, инициализация рабочих директорий и запуск окна PySide6 |
| `config.py` | Пути, интервалы таймеров, пороги качества сигнала и параметры ребалансировки |
| `core/capsule_bridge.py` | Интеграция с `CapsuleClientPython`, BLE-сканер, пакетная обработка и `DemoCapsuleController` |
| `core/media_monitor.py` | Чтение текущего трека и статуса воспроизведения через Windows SMTC (`winrt`) |
| `core/emotion_engine.py` | Расчёт качества срезов, нормализация вектора эмоций и адаптивная ребалансировка весов |
| `core/hdf5_store.py` | Поточная запись и чтение HDF5-файлов сессий (структура Neiry 3.0 + маркеры треков) |
| `core/track_db.py` | SQLite-хранилище сессий, истории прослушиваний и профилей калибровки |
| `core/models.py` | Типизированные dataclass-модели треков, срезов, калибровок и агрегированных профилей |
| `ui/main_window.py` | Десктопный интерфейс PySide6 с живыми графиками `pyqtgraph` и 3 вкладками |
| `tests/test_core.py` | Юнит-тесты ребалансировки весов, персистентности SQLite и симулятора |

## Стек технологий

- **Язык и UI:** Python 3.11+, PySide6 (Qt 6), pyqtgraph
- **Данные и хранение:** NumPy, h5py (HDF5), SQLite (`sqlite3`)
- **Интеграции:** Neiry Capsule API (`CapsuleClient.dll` + `CapsuleClientPython`), Windows SMTC (`winrt-Windows.Media.Control`)

## Установка и запуск (Windows)

### 1. Подготовка SDK
Библиотеки Neiry Capsule API являются проприетарными и не входят в репозиторий. После клонирования поместите в корень проекта (рядом с `app.py`):
- папку `CapsuleClientPython/` из вашего пакета CapsuleAPI;
- нативную библиотеку `CapsuleClient.dll` (x64).

*(Рекомендуется добавить `CapsuleClientPython/`, `CapsuleClient.dll` и `data/` в `.gitignore`.)*

### 2. Установка зависимостей
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```
*(Если PowerShell блокирует активацию скриптов, выполните один раз `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.)*

### 3. Запуск приложения и тестов
```powershell
# Запуск приложения
python app.py

# Запуск юнит-тестов ядра
python -m unittest discover -s tests -v
```

## Быстрая проверка работы

- **Без повязки (Demo-режим):** выберите в выпадающем списке `Demo (без повязки)`, нажмите **«Сканировать и подключить»** и включите музыку в Spotify — приложение подхватит трек через Windows SMTC, построит графики, запишет `.h5` в `data/sessions/` и добавит запись в «Библиотеку треков».
- **С реальным Neiry Headband:** полностью закройте оригинальное приложение Capsule (оно удерживает BLE-соединение), переведите повязку в режим поиска (зажмите кнопку до частого зелёного мигания), выберите `Any (все Neiry / BrainBit)` и нажмите **«Сканировать и подключить»**. Для снижения артефактов морганий рекомендуется оставить включённым **«Биполярный»** режим.
